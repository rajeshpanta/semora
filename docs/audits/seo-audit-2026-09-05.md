# Semora SEO audit

Audited September 5, 2026 (Pacific), https://semoraai.com. Read-only production audit plus source review; no website changes or deployment. The adjacent CSV contains the 92-page sitemap inventory.

## Assessment

The technical foundation is sound in the checks performed. The largest opportunities are clearer differentiation between overlapping pages, evidence that demonstrates the product, and measurement of which search visits become active users. There is also a confirmed HTML hreflang defect and outdated Spanish product copy. These findings do not establish why a particular page ranks where it does.

## What is working

- All 92 sitemap URLs returned HTTP 200. Each had a nonempty, unique title and meta description, exactly one H1, and a matching self-canonical URL. None advertised noindex in the inspected HTML or response headers.
- Every sitemap page had at least one incoming HTML link from another crawled page. This is an internal-link inventory, not a measurement of link quality.
- robots.txt permits crawling and advertises the correct sitemap. HTTP and www homepage variants return permanent 308 redirects to the HTTPS apex. A deliberately nonexistent marketing URL returned a real 404.
- Meaningful page copy is present in the initial HTML, making it accessible without waiting for client-side rendering.
- English/Spanish localization, language switching, and sitemap alternates are implemented. One inconsistent pair is detailed below.
- WebSite, Organization, SoftwareApplication, Article, BreadcrumbList and FAQPage markup appear across relevant page types. JSON parsing succeeded in the inspected blocks; that is not a Google rich-result eligibility test.
- The sampled app login route returns X-Robots-Tag: noindex, nofollow, helping keep the signed-in app separate from public marketing content.
- Useful acquisition assets already exist: the GPA calculator, Pomodoro timer, syllabus scanner landing page, Canvas pages, comparison pages and practical blog guides. The homepage already includes product screenshots.
- The AI study-app comparison discloses that Semora publishes it and that it is a desk review, with sourcing and caveats. This is a worthwhile editorial practice to preserve.
- Public search results surfaced the homepage, scanner landing page and a syllabus guide. This establishes some search visibility, not complete Google indexing or rankings.

## Prioritized findings

### 1. Fix the GPA calculator language annotations — confirmed, small fix

The live English /gpa-calculator HTML declares its Spanish alternate as /es/blog/calcular-gpa-ponderado. That old URL redirects. The actual Spanish calculator is /es/calculadora-gpa and it correctly points back to the English calculator. The sitemap and language switcher already use the current URL.

In website/lib/hreflang.ts, EN_TO_ES is populated from SPANISH_PAGES. The retained old Spanish article has the same englishPath and overwrites the calculator mapping. Derive HTML alternates from the shared indexable route-pair registry or exclude retired routes. Update the Spanish blog index link to the current calculator too.

Acceptance: both calculators emit the same reciprocal en-US, es and x-default set using final 200 URLs; HTML and sitemap agree. This is a consistency defect, not proof that all Spanish indexing is broken. [Google's localized-page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions).

### 2. Correct outdated Spanish Canvas instructions — confirmed

/es/acerca-de says Canvas connectivity depends on a token and institutional policy. /about says users paste the private Calendar Feed link, without generating an access token or requiring school approval. This contradiction can discourage Spanish-speaking students from trying the product.

The stale sentence appears in website/lib/es-content.ts around line 180. Align both languages with the shipping connection flow and audit other Spanish setup and plan-limit statements when product behavior changes.

### 3. Give overlapping pages distinct jobs — opportunity, ranking impact unconfirmed

Examples:

| Pages | Recommended distinction |
| --- | --- |
| /ai-syllabus-scanner and /features/syllabus-scanner | Primary category/acquisition page versus detailed product workflow and supported inputs |
| /canvas-deadline-tracker and /features/canvas-sync | Solve the missed-deadline problem versus explain connection setup, sync timing and limitations |
| /shovel-alternative and /compare/shovel | Help a switching user migrate versus provide a direct feature comparison |

Several pairs cover much of the same subject. That is a potential search-intent overlap, not confirmed keyword cannibalization. In Search Console, inspect queries and the pages receiving impressions for each query before choosing a winner. Refocus titles, headings, copy and contextual links. Merge and 301 only when two pages serve substantially the same purpose and there is evidence supporting consolidation; do not blindly canonicalize distinct pages.

### 4. Add visible evidence to high-intent pages — high-value content work

The scanner landing page is largely text; its fetched HTML contained no image elements. The feature page includes an illustrative interface, while actual product screenshots are available on the homepage. The scanner pages' extracted text is approximately 4,100–4,400 words including shared navigation/footer. Length itself is not a defect, but these pages would benefit from faster proof near the top.

Show a permitted or anonymized syllabus sample, the actual extraction/review screen, and the resulting calendar. Explain a real ambiguous date and how the review step handles it. Add a short captioned walkthrough and a downloadable sample so visitors can understand the result before signing up. Keep free-plan limits near the CTA.

For comparisons, augment the existing honest desk-review methodology with firsthand testing when feasible. Use dated screenshots, reproducible examples, and clearly marked limitations; do not invent results or testimonials. [Google's people-first content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

### 5. Make authorship more informative — trust and conversion opportunity

Blog bylines identify Semora and link to About. The About page explains architecture and independence at length, but the inspected text does not identify the individual builder. Add a genuine name/bio or verifiable publisher identity, relevant experience, and a concise explanation of why the product was built. Put implementation detail below the student-facing explanation. A named individual is not a prerequisite for ranking; the purpose is to make ownership and experience easier to assess.

Collect permissioned student case studies and real feedback as they become available. A domain-based support address could improve presentation, but it is not an established direct ranking factor.

### 6. Strengthen selected contextual links — confirmed limited incoming links

The English first-two-weeks-of-semester and how-to-study-for-midterms articles each had links from only two distinct crawled pages. The Spanish versions and Spanish assignment-weights article also had two. This does not make them orphaned, but gives them limited contextual discovery.

Add useful links from relevant older guides: semester setup to first-two-weeks, finals planning to midterms, and grade tracking/calculator content to assignment weights. Prefer a sentence explaining why the linked guide helps; the footer already provides broad site coverage.

### 7. Verify measurement before expanding content — access required to establish results

GA4 integration code exists, but the fetched homepage HTML did not contain the Google tag URL. That observation alone does not prove analytics is broken. Verify the production configuration and browser network requests, then confirm events arrive in the analytics property. Vercel/custom telemetry code also exists.

Use Search Console for the last 90 days of queries/pages, clicks, impressions, CTR, device, country, indexed/excluded pages and selected canonicals. Split branded from nonbranded search and English from Spanish. Use analytics to connect organic landing pages to signup, first successful syllabus scan or LMS connection, and subscription. Verify attribution survives the move to app.semoraai.com.

No authenticated Search Console, analytics or backlink dataset was accessed. Do not infer zero backlinks, low traffic, ranking losses or missing account setup from this audit.

## Performance and structured data limits

Google's public PageSpeed API returned HTTP 429, so there is no defensible mobile performance score or Core Web Vitals pass/fail result here. No rendered mobile-browser usability audit was completed. Run PageSpeed on the homepage, scanner page and calculator, and inspect real-user data in Search Console. Target LCP within 2.5 seconds, INP below 200 ms and CLS below 0.1, assessed with field data where available. [Google's Core Web Vitals guidance](https://developers.google.com/search/docs/appearance/core-web-vitals).

The application schema describes the product but should not be assumed to qualify for software-app rich results: Google's requirements include a review or aggregate rating. Add only genuine eligible ratings displayed on the page. [Google's software-app schema requirements](https://developers.google.com/search/docs/appearance/structured-data/software-app).

Spanish comparison/alternative pages sampled outside the sitemap intentionally returned noindex, follow. Source comments explicitly describe this as temporary pending content improvement. Do not indiscriminately remove those directives or add those pages to the sitemap.
