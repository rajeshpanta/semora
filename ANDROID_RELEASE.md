# Semora Android release setup

Companion to `DEPLOYMENT.md`, which covers the two web surfaces. This one covers
signing and store setup for the Android build, which did not exist before
2026-08-21 (the app was iOS-only until then).

Nothing secret lives in this file or anywhere else in the repository. The
keystore password is in `~/Semora-Recovery/ANDROID_KEYSTORE.txt` (chmod 600),
alongside the Apple `.p8` keys.

## Toolchain

Android is not installed system-wide on the build Mac — there is no Android
Studio and no `~/Library/Android/sdk`. Everything comes from Homebrew, and the
three variables below have to be set for any `gradlew` / `adb` / `emulator`
call. `scripts/run-android.sh` sets them itself.

| Variable | Value |
| --- | --- |
| `JAVA_HOME` | `/opt/homebrew/opt/openjdk@17` (system Java is 22; RN 0.81 needs 17) |
| `ANDROID_HOME` | `/opt/homebrew/share/android-commandlinetools` |
| `ANDROID_SDK_ROOT` | same as `ANDROID_HOME` |

## Identity

| Field | Value |
| --- | --- |
| Package / applicationId | `com.rajeshpanta.syllabussnap` (matches the iOS bundle id) |
| Subscription product IDs | `semora_pro_monthly`, `semora_pro_annual` (must match App Store Connect) |

## Upload keystore

| Field | Value |
| --- | --- |
| File | `~/Semora-Recovery/semora-upload.keystore` |
| Alias | `semora-upload` |
| Algorithm | RSA 2048, valid to 2054 |
| Password | `~/Semora-Recovery/ANDROID_KEYSTORE.txt` — never in the repo |

This is the **upload key**, not the app signing key. Play App Signing is
mandatory for new apps, so Google generates and holds the key that actually
signs what users install; a lost upload key can be reset through Play Console
support. Back it up regardless — a reset is a support round-trip you do not want
in the middle of a release.

## SHA-1 fingerprints

Google Sign-In on Android matches the package name against a certificate
fingerprint, so **every** certificate that will ever sign the app needs its own
entry on the Android OAuth client in Google Cloud. There are three, and the
third one does not exist until after the first Play upload:

| Certificate | SHA-1 | Needed for |
| --- | --- | --- |
| Upload key | `6B:07:F2:13:5B:0E:75:03:16:31:FC:F5:D4:89:CB:3E:7B:20:73:D8` | Builds you sign locally |
| Debug key (`android/app/debug.keystore`) | `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25` | `bundleDebug` / emulator testing |
| Play App Signing | issued by Google after the first upload | Anything installed **from Play** |

Miss the third and Google sign-in works everywhere except the builds real users
get, which is the worst possible place to find out.

Re-read a fingerprint with:

```
keytool -list -v -keystore ~/Semora-Recovery/semora-upload.keystore -alias semora-upload
```

## Why signing is a config plugin

`android/` is gitignored and regenerated by `expo prebuild`, and the template it
regenerates signs the **release** buildType with `debug.keystore` — its own
comment says "Caution! In production, you need to generate your own keystore
file." So editing `android/app/build.gradle` by hand lasts exactly until the next
prebuild, and the failure is silent: you get an AAB signed with a debug key.

`plugins/withAndroidUploadSigning.js` (registered in `app.json`) therefore
re-applies the release `signingConfigs` block on every prebuild. It reads four
Gradle properties from `~/.gradle/gradle.properties`, which lives outside the
repository so the password is never committable:

```
SEMORA_UPLOAD_STORE_FILE
SEMORA_UPLOAD_STORE_PASSWORD
SEMORA_UPLOAD_KEY_ALIAS
SEMORA_UPLOAD_KEY_PASSWORD
```

When those properties are absent the plugin falls back to debug signing rather
than failing, so a fresh clone or a CI machine without the keystore still
builds.

## Why release lint is patched too

`plugins/withAndroidReleaseLint.js` disables exactly one lint check,
`ExtraTranslation`, for the same regenerated-directory reason.

`app.json` maps `locales.es -> ./locales/es.json`, which holds the eight **iOS**
Info.plist permission descriptions. Expo mirrors that file into the Android
resource tree as `res/values-b+es/strings.xml`, where those keys mean nothing —
Android permission rationale is not read from string resources named
`NSCameraUsageDescription`. Since they exist only in the Spanish folder and never
in the default one, lint raises `ExtraTranslation` eight times and
`lintVitalRelease` aborts the build.

Debug builds do not run `lintVitalRelease`, which is why the app ran on the
emulator for days before the first `bundleRelease` surfaced this.

Only that one check is disabled — every other lint error still fails a release
build. Deleting the generated folder was rejected because it would also withdraw
Spanish from Android's per-app language picker, and prebuild would rewrite it on
the next run anyway.

## Building

```
# Debug on the emulator (starts the AVD, builds, installs, launches)
./scripts/run-android.sh

# Signed artifact for Play
cd android && ./gradlew :app:bundleRelease
# -> android/app/build/outputs/bundle/release/app-release.aab
```

Verify what actually signed an artifact before uploading:

```
keytool -printcert -jarfile android/app/build/outputs/bundle/release/app-release.aab
```

If that prints the debug fingerprint, the Gradle properties were not picked up.
